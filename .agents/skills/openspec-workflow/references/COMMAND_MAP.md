# COMMAND MAP

Use este mapa quando o pedido já estiver claramente dentro de OpenSpec/OPSX e você precisar escolher o workflow sem reabrir todos os prompts.

| Comando / intenção                                         | Workflow canônico | Regra de seleção da change                                                                                                      | Fonte de verdade do schema                                                                          | Condição de parada                                                                                                  |
| ---------------------------------------------------------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `/opsx:new` ou "cria uma change"                           | `opsx-new`        | Não há seleção prévia; executa preflight spec check, valida/derive o nome da nova change                                        | Schema `spec-driven` do runtime instalado                                                           | Para depois de mostrar o primeiro artefato `ready`                                                                  |
| `/opsx:continue` ou "cria a próxima proposal/design/tasks" | `opsx-continue`   | Sempre seleção explícita se o nome não vier no pedido                                                                           | `opsx status --change "<name>" --json` e `opsx instructions <artifact-id> --change "<name>" --json` | Para após criar um único artefato `ready`                                                                           |
| `/opsx:ff` ou "gera tudo até apply-ready"                  | `opsx-ff`         | Nova change; executa preflight spec check; se o nome já existir, confirmar continuidade                                         | Schema `spec-driven` do runtime instalado                                                           | Para quando `apply.requires` estiver satisfeito                                                                     |
| `/opsx:review` ou "revisa a change antes de implementar"   | `opsx-review`     | Sempre seleção explícita se o nome não vier no pedido                                                                           | Bundle gate, artefatos completos e fonte de decisão                                                 | Emite achados em modo read-only; não implementa nem edita artefatos                                                 |
| `/opsx:apply` ou "implementa as tasks da change"           | `opsx-apply`      | Exceção: pode inferir da conversa ou auto-selecionar se houver uma única change ativa segura; caso contrário, seleção explícita | Provenance preflight, bundle gate, autorização separada, `opsx status` e `opsx instructions apply`  | Para em blocker; sucesso só com o apply-exit mecânico atual. Verify, sync, completion e archive continuam separados |
| `/opsx:verify` ou "verifica antes de arquivar"             | `opsx-verify`     | Sempre seleção explícita se o nome não vier no pedido                                                                           | Status, artefatos, implementação e `opsx fingerprint`                                               | Grava `evidence/verification-report.json` e exige completion verde                                                  |
| `/opsx:sync` ou "sincroniza delta specs"                   | `opsx-sync`       | Sempre seleção explícita se o nome não vier no pedido                                                                           | `openspec/changes/<name>/specs/*/spec.md` mais `openspec/specs/<capability>/spec.md`                | Executa `opsx-sync --change "<name>" --json`, prova idempotência com `--check` e para                               |
| `/opsx:archive` ou "arquiva a change"                      | `opsx-archive`    | Sempre seleção explícita se o nome não vier no pedido                                                                           | Completion gate, status, tasks e delta specs                                                        | Para sem mover se completion falhar; não há override                                                                |
| `/opsx:explore` ou "explora essa ideia/change"             | `opsx-explore`    | Use o nome da change apenas como contexto                                                                                       | `opsx list --json` e leitura de artefatos                                                           | Read-only; persistência segue por `continue` ou `ff`                                                                |

## Notas rápidas

- O layout ativo principal é diretório por change: `openspec/changes/<name>/`.
- Não trate arquivos soltos `openspec/changes/*.md` como default operacional.
- O runtime instalado suporta `spec-driven`; outro schema exige suporte explícito, sem fallback para validação parcial.
